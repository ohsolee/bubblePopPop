# 단어사전 — 비눗방울 팡팡

> 둘 다 고도(Godot) 처음이라, 설계서와 코드에 나오는 용어를 초보자 눈높이로 정리했어요.
> 모르는 단어가 나오면 여기서 찾아보세요. 새 용어를 만나면 자유롭게 추가하면 됩니다.
> (남편분은 언리얼 경험이 있어서, 도움이 되는 곳엔 언리얼 비유를 붙였어요.)

---

## 1. 고도의 가장 기본 개념

| 용어 | 뜻 | 쉽게 말하면 |
|------|-----|------------|
| **노드 (Node)** | 고도의 가장 작은 부품 하나. 이미지, 소리, 타이머 등 모든 게 노드다. | 레고 블록 1개 |
| **씬 (Scene)** | 노드들을 조립해 만든 하나의 덩어리. `.tscn` 파일로 저장됨. | 레고로 완성한 자동차 한 대 |
| **씬 트리 (Scene Tree)** | 노드들이 부모-자식으로 연결된 나무 구조. | 가족 관계도 |
| **루트 노드 (Root Node)** | 씬에서 가장 위(부모)에 있는 노드. | 나무의 뿌리 |
| **인스펙터 (Inspector)** | 선택한 노드의 속성을 보고 바꾸는 오른쪽 패널. | 부품 설정 창 |
| **`res://`** | 프로젝트 폴더의 최상단을 가리키는 주소. `res://scenes/Main.tscn` = 프로젝트 안 scenes 폴더의 Main.tscn | 프로젝트 안에서의 "집 주소" |

> **언리얼 비유:** 씬(.tscn) ≈ 블루프린트 클래스 / 노드 ≈ 컴포넌트나 액터

---

## 2. 파일 종류

| 용어 | 뜻 |
|------|-----|
| **`.tscn`** | 씬 파일. 노드 구조가 저장됨. **(지용 담당)** 텍스트라 git이 읽을 수 있음 |
| **`.gd`** | GDScript 파일. 게임 로직 코드. **(아내 담당)** |
| **`.import`** | 이미지·소리를 넣으면 고도가 자동으로 만드는 설정 파일. 직접 건드리지 않음 |
| **`project.godot`** | 프로젝트 전체 설정 파일 (해상도, 렌더러 등). 커밋하면 모두에게 공유됨 |

---

## 3. 이 게임에 쓰는 노드들

| 노드 | 하는 일 | 이 게임에서 |
|------|---------|------------|
| **Node2D** | 2D 공간의 기본 노드 (위치·회전·크기를 가짐) | Main, BubbleContainer의 바탕 |
| **Sprite2D** | 이미지 한 장을 화면에 그림 | 배경, 비눗방울 그림, 캐릭터 그림 |
| **Area2D** | "영역"을 만들어 터치·충돌을 감지 | 방울 1개 = Area2D (터치 판정) |
| **CollisionShape2D** | Area2D가 감지할 실제 모양(원·사각형) | 방울의 터치 범위 (원, 그림보다 20% 크게) |
| **CircleShape2D** | 원 모양 충돌 형태 | 방울은 동그라니까 원 사용 |
| **Timer** | 정해진 시간마다 신호를 보냄 | SpawnTimer — 1.2초마다 방울 생성 |
| **CanvasLayer** | 항상 화면 맨 앞에 고정되는 층 (UI용) | UILayer — 별 카운터가 흔들리지 않게 |
| **HBoxContainer** | 자식들을 가로로 나란히 배치 | 별 아이콘 + 숫자를 가로로 |
| **Label** | 글자를 화면에 표시 | 별 개수 숫자 |
| **TextureRect** | UI용 이미지 표시 | 별 아이콘 |
| **AudioStreamPlayer2D** | 소리를 재생 | 방울 터지는 "퐁" 소리 |
| **CPUParticles2D** | 작은 입자를 뿌리는 효과 (CPU로 계산) | 방울 터질 때 물방울 튀는 파티클 |

> **왜 GPUParticles가 아니라 CPUParticles2D?**
> 웹(브라우저)에서 돌릴 때 GPU 방식은 안 될 수 있어서, 어디서나 안전한 CPU 방식을 씀. (설계서 67줄)

## 4. 코드에서 자주 보는 말

| 용어 | 뜻 | 예시 |
|------|-----|------|
| **인스턴싱 (instancing)** | 씬을 복제해서 실제로 하나 만들어냄 | 방울 씬 1개로 화면에 방울 수십 개 생성 |
| **`instantiate()`** | 인스턴싱을 실행하는 명령 | `bubble_scene.instantiate()` |
| **`preload()`** | 씬·파일을 게임 시작 전에 미리 불러둠 (빠름) | `preload("res://scenes/Bubble.tscn")` |
| **`add_child()`** | 어떤 노드 밑에 자식 노드를 붙임 | 만든 방울을 화면에 붙이기 |
| **`queue_free()`** | 노드를 안전하게 삭제 예약 | 화면 밖으로 나간 방울 정리 |
| **`_ready()`** | 노드가 처음 준비되면 딱 1번 자동 실행되는 함수 | 초기값 세팅할 때 |
| **`_process(delta)`** | **매 프레임마다** 자동 실행되는 함수 | 방울을 조금씩 위로 이동 |
| **`delta`** | 지난 프레임에서 지금까지 걸린 시간(초) | 컴퓨터 성능과 무관하게 일정한 속도를 내기 위해 곱해줌 |

> **왜 delta를 곱하나?** 빠른 PC든 느린 PC든 방울이 **같은 속도**로 움직이게 하려고.
> `speed * delta` = "1초에 speed만큼" 움직이는 셈.

## 5. 시그널 (이 프로젝트의 핵심!)

| 용어 | 뜻 | 쉽게 말하면 |
|------|-----|------------|
| **시그널 (signal)** | 어떤 일이 일어났다고 알리는 "방송" | 초인종 |
| **`emit`** | 시그널을 보냄 (방송함) | 초인종을 누름 |
| **`connect`** | 시그널을 받으면 실행할 함수를 연결 | "초인종 울리면 나가서 문 열기"를 등록 |
| **커스텀 시그널** | 내가 직접 만든 시그널 | `popped(pos, is_character)` — 방울이 터졌다고 알림 |
| **`input_event`** | Area2D가 터치/클릭될 때 자동으로 오는 시그널 | 방울을 눌렀을 때 |

> **이 게임의 신호 흐름:**
> 방울을 터치 → 방울이 `popped` 시그널을 **emit** → Main이 그걸 **connect**해서 듣고 있다가 → 별 카운터 증가 + 파티클 생성
>
> **언리얼 비유:** 시그널 = 이벤트 디스패처(Event Dispatcher), input_event = OnClicked 이벤트 (설계서 61줄)

## 6. 연출 (지용 담당)

| 용어 | 뜻 |
|------|-----|
| **Tween** | 값을 부드럽게 변하게 하는 애니메이션 도구 (크기·위치·투명도 등) |
| **`create_tween()`** | Tween을 하나 만듦 |
| **scale** | 크기 (1.0 = 원래, 1.3 = 30% 크게) |
| **바운스 (BOUNCE)** | 통통 튀는 느낌의 움직임 곡선 |
| **이징 (Easing)** | 움직임이 빨라지거나 느려지는 완급 |
| **페이드아웃 (fade out)** | 서서히 투명해지며 사라짐 |
| **one_shot** | 파티클을 딱 한 번만 터뜨리고 멈춤 |

> **언리얼 비유:** Tween 이징 ≈ 언리얼의 커브 이징 (같은 개념)

## 7. 랜덤 / 기타

| 용어 | 뜻 |
|------|-----|
| **`randf_range(a, b)`** | a~b 사이의 **소수** 랜덤값 (예: 속도) |
| **`randi_range(a, b)`** | a~b 사이의 **정수** 랜덤값 (예: 6~8개) |
| **보장형 카운터** | 순수 랜덤 대신, "N개마다 반드시 1번"을 보장하는 방식. 유아가 지루하지 않게 (설계서 28줄) |
| **`set_deferred()`** | 지금 당장이 아니라 "안전한 타이밍에" 값을 바꿈. 충돌 처리 중 오류 방지용 |
| **가드 (guard)** | 중복 실행을 막는 안전장치. `is_popped`로 방울이 두 번 터지는 걸 방지 |

## 8. 배포 / 환경

| 용어 | 뜻 |
|------|-----|
| **렌더러 (Renderer)** | 화면을 그리는 방식. 이 프로젝트는 **Compatibility**(웹 호환 최우선) |
| **웹 익스포트 (Web Export)** | 게임을 브라우저에서 돌아가는 형태(HTML5)로 내보내기 |
| **GitHub Pages** | GitHub이 무료로 제공하는 웹사이트 호스팅. 완성된 게임을 링크로 공유 |
| **Stretch Mode** | 화면 크기가 달라도 게임이 잘 늘어나 보이게 하는 설정 |
| **Emulate Touch From Mouse** | PC에서 마우스 클릭을 터치처럼 인식 (폰 없이 테스트용) |

## 9. Git 협업 용어

| 용어 | 뜻 |
|------|-----|
| **commit (커밋)** | 변경사항을 하나의 기록으로 저장 |
| **push (푸시)** | 내 커밋을 GitHub에 올림 |
| **pull (풀)** | GitHub의 최신 내용을 내 PC로 받음 |
| **충돌 (conflict)** | 두 사람이 같은 부분을 동시에 고쳤을 때 발생. 그래서 파일 소유권을 나눔 (설계서 6장) |
| **`.gitignore`** | git이 무시할 파일 목록 (예: `.godot/` 임시 캐시) |
| **`.gitkeep`** | 빈 폴더도 git에 올리기 위한 관례용 빈 파일 |

---

> 📌 **작업 규칙 한 줄 요약:** 작업 시작 전 `git pull`, 끝난 후 `git push`. 씬은 지용, 스크립트는 아내. (설계서 6장)
